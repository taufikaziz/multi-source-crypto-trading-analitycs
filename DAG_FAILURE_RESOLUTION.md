# DAG Failure Resolution Summary

This document details the step-by-step diagnostic and resolution process for the `indodax_market_pipeline` DAG failure.

## Identified Issues

1. **Missing DuckDB Dependency in Docker Image**
   * **Symptom**: The DAG task `run_indodax_pipeline` immediately failed while still in the queued state, leaving an empty or single-line log file (`attempt=1.log`).
   * **Root Cause**: The Python environment inside the Airflow Docker containers was missing the `duckdb` library. The pipeline requires `duckdb` via `src.warehouse.connection`, causing an immediate `ModuleNotFoundError` during task startup before standard error could be redirected to the task logs.

2. **Inconsistent Secret Keys (JWT Signature Verification Failure)**
   * **Symptom**: Airflow 3 Task SDK failed to authenticate with the execution API server, producing:
     `airflow.sdk.api.client.ServerResponseError: Invalid auth token`
     `jwt.exceptions.InvalidSignatureError: Signature verification failed`
   * **Root Cause**: The JWT token generated by the scheduler could not be verified by the API server because `AIRFLOW__API__SECRET_KEY` was not configured in `airflow-docker/.env`. Each container generated its own random key at startup, causing signature mismatches.

3. **Placeholder Databricks Configurations**
   * **Symptom**: Headless tasks could not authenticate with Databricks using `"databricks-oauth"`.
   * **Root Cause**: Host-level environment variables were not loaded into the docker containers, leaving `DATABRICKS_SERVER_HOSTNAME` and `DATABRICKS_HTTP_PATH` as `REPLACE_ME`.

---

## Action Steps Taken

### Step 1: Install Missing Dependencies
* Modified `airflow-docker/Dockerfile` to install `duckdb` inside the container image.

### Step 2: Configure Environment Variables
* Replaced the `REPLACE_ME` placeholders for `DATABRICKS_SERVER_HOSTNAME` and `DATABRICKS_HTTP_PATH` in `airflow-docker/.env` with the actual connection values from the host `.env`.
* Configured `PYTHONPATH` to `/opt/airflow/src` inside `airflow-docker/.env` to ensure proper import resolutions.

### Step 3: Standardize the API Secret Key
* Added `AIRFLOW__API__SECRET_KEY=4zETXRvmaVfNbl3/XdJY+Q==` to `airflow-docker/.env` to ensure consistent signature generation and verification between the scheduler and the API server.

### Step 4: Robust Headless Authentication Support
* Patched `src/warehouse/databricks_loader.py` to check for `DATABRICKS_TOKEN`. If present, it uses `auth_type="access-token"` to allow non-interactive headless execution. If not, it defaults to the interactive `"databricks-oauth"`.

### Step 5: Container Rebuild and Restart
* Ran `docker compose up --build -d` to rebuild the Docker image with the new dependencies and restart services with the updated environment configs.

## How to View and Verify

### 1. View this Summary File
To view this Markdown file from the command line, run:
```powershell
Get-Content -Path "DAG_FAILURE_RESOLUTION.md"
```

### 2. Verify Airflow Containers and Configs
Run the following to check that the scheduler and API server now share the exact same API secret key configuration:
```powershell
docker exec indodax-airflow-scheduler airflow config list --show-values | Select-String -Pattern "secret_key = "
docker exec indodax-airflow-api airflow config list --show-values | Select-String -Pattern "secret_key = "
```

### 3. Trigger and Verify DAG Execution
To trigger the DAG and verify that it completes successfully, run:
```powershell
docker exec indodax-airflow-scheduler airflow dags trigger indodax_market_pipeline
```
Wait a few seconds, then check the state of the runs:
```powershell
docker exec indodax-airflow-scheduler airflow dags list-runs indodax_market_pipeline
```
